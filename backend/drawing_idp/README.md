# Чертежи. Препроцессинг и проверка результата

Пакет работает локально на Python 3.12. Установите зависимости через `python -m pip install -r backend/drawing-idp-requirements.txt`.

```powershell
python -m backend.drawing_idp preprocess drawing.pdf data/prepared --page 81
python -m backend.drawing_idp schema --input
python -m backend.drawing_idp validate drawing.pdf data/review --extraction extraction.json --catalogue catalogue.csv
python -m backend.drawing_idp schema
```

Обе команды обработки принимают PDF, PNG, JPEG и другие изображения, поддерживаемые Pillow. Уберите `--page` для обработки всего PDF. Укажите отдельную выходную папку для каждого запуска. Для формата шифров конкретного проекта передайте `--drawing-code-pattern`. Проверка применяет шаблон ко всей строке после нормализации регистра и пробелов.

## Модуль 1

В `manifest.json` перечислены страницы и SHA-256 источника. Файл `page-NNNN.json` хранит текстовые фрагменты, их шрифты и координаты. Векторная страница с текстом сохраняется без растеризации. Страница со сканом, смешанным содержимым или текстом, переведённым в контуры, получает изображения в градациях серого и после бинаризации. PDF рендерится с 300 DPI по умолчанию. Фрагмент изображения сохраняет исходное разрешение.

Координаты `pdf_pt` отсчитываются от верхнего левого угла страницы без применения флага её поворота. Координаты `image_px` отсчитываются в исходном изображении после применения EXIF-ориентации. Матрица `pixel_to_source` преобразует координаты изображения после выравнивания в координаты источника. Для прямоугольника преобразуйте все четыре угла. В Python это делает `PreparedPage.source_box`.

## Модуль 4

Команда `validate` принимает JSON от распознавателя или от оператора. Вот минимальный вход для чтения штампа на странице PDF.

```json
{
  "stamp": {
    "drawing_code": {
      "value": "АБВГ.123456.001",
      "confidence_score": 0.93,
      "source": {
        "page": 1,
        "space": "pdf_pt",
        "bbox": {"x0": 80, "y0": 120, "x1": 160, "y1": 135}
      },
      "raw_text": "АБВГ.123456.001"
    }
  }
}
```

Количества и массы передаются десятичными строками с точкой. В `raw_text` сохраните число из ячейки в исходном виде с десятичной запятой или точкой. Укажите `null`, если ячейка не читается. Для проверки массы `unit_mass` и `total_mass` должны иметь общую единицу `mass_unit`. По умолчанию расхождение допускается в пределах большей из двух величин — 0,01 кг или 0,5% расчётной массы.

CSV справочника использует UTF-8 и два столбца `kind,value`. Типы записей — `name`, `material`, `steel_grade`. Однозначную замену похожих символов пакет записывает в аудит `corrections`. Обычное похожее совпадение отображается в очереди как предложение.

В выходной папке есть `result.json`, очередь `review.jsonl` и исходные кропы в `crops/`. Строки со спорными полями имеют `needs_review: true`. Если координаты вне страницы, задача сохраняется в очереди с пустым `crop_path`. Расчётный итог по массе выводится отдельно от прочитанного значения.

## Проверка качества при подключении распознавателя

Сравнивайте результаты на одном размеченном наборе, включая векторные документы, сканы и текст в контурах. Измеряйте долю найденных строк, долю точных полей среди автоматически принятых, ошибки в количествах и единицах, а также долю полей в ручной очереди. Высокая точность среди принятых полей при низком покрытии оставит оператору много ручной работы.
