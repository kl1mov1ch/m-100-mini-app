# PostgreSQL на сервере с 1 ГБ памяти

Рабочая схема разделена на registry и journal. Связи и внешние ключи проверяются PostgreSQL; строки объектов защищены RLS. Для приложения используется отдельная роль без SUPERUSER и BYPASSRLS.

SQLAlchemy управляет пулом из трёх подключений с одним дополнительным подключением, транзакциями и ORM-моделями. Чтение сметы, пакетная история и настройки используют ORM. Остальные операции пока используют совместимый SQL-слой в той же транзакции; полный отказ от прямых запросов ещё не завершён.

История загружается двумя пакетными запросами вместо чтения каждого дня отдельно. Настройки читаются один раз на транзакцию; постоянного межпользовательского кэша нет.

PostgreSQL: shared_buffers 32 МБ, work_mem 2 МБ, maintenance_work_mem 32 МБ, максимум 20 соединений, JIT и параллельные запросы отключены. Контейнер ограничен 256 МБ и одним CPU. Порт доступен только на 127.0.0.1.

Перед переключением создаётся согласованный архив SQLite, проверяются количества записей и суммы по каждому дню. Старые файлы сохраняются для аварийного отката. После начала записи в PostgreSQL автоматический возврат к старой SQLite запрещён: сначала нужно перенести новые записи.

Штатная резервная копия содержит pg_dump в custom-формате и отдельный архив исходных файлов. Для восстановления нужны также защищённые настройки подключения и роли. Восстановление проверяется в отдельной базе.
