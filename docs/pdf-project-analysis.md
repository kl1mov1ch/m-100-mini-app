# PDF → проверяемая смета

Ветка разработки: `codex/pdf-project-analysis`. Пользователь загружает PDF и формулирует запрос, например «вентиляция» или «теплопровод». Все страницы обрабатываются в фоне. Результат открывается отдельной страницей: группы работ, объёмы, единицы, расценки, источники и вопросы.

## Обработка

1. Файл до 50 МБ сохраняется в закрытом каталоге по случайному ID. Повторная загрузка того же файла с тем же запросом возвращает существующее задание владельца.
2. pypdf читает текстовый слой; для сканов Poppler создаёт изображение, Tesseract читает русский и английский текст. Координаты источников сохраняются для подсветки на странице.
3. Для крупных таблиц определяется сетка, ячейки распознаются отдельными фрагментами. Числовые ячейки повторно проверяются увеличенным изображением. Расхождения OCR сохраняются, а не скрываются.
4. ИИ разбирает все текстовые фрагменты по запросу. Заголовки таблицы передаются с фрагментами. Для табличной строки сервер восстанавливает цитату по её номеру и сверяет ячейку количества с указанной колонкой; привязку дополнительно проверяет ИИ.
5. Повторы фрагментов удаляются. Одинаковые работы объединяются только при совпадении категории, названия, единицы и условий. Разные размеры и условия остаются отдельными. Пересечение систем и неподтверждённые повторы блокируют автоматическое суммирование.
6. Единицы приводятся размерно: м.п. → м без изменения объёма и ставки; мм/см/км → м, см² → м², литры → м³, граммы/тонны → кг. Метры не превращаются в квадратные метры без отдельных исходных размеров.

## Проверка мастером

- Поиск, категории, фильтр неподтверждённых строк и страницы по восемь карточек.
- Расценки вводятся прямо в карточках. Несколько проверенных строк можно подтвердить одним действием; спорные объёмы требуют явного решения: сумма, один экземпляр или ручное уточнение.
- В источниках доступны дословные строки, исходные единицы, преобразование и изображение PDF с подсветкой.
- Изменения сохраняются с автором, временем и значениями до/после. Проверка версии предотвращает подтверждение устаревших данных. Массовое подтверждение выполняется одной транзакцией.
- Итоговый Excel доступен после подтверждения всех строк и расценок, полноты обработки и предупреждений. До этого доступен Excel-черновик.
- Excel содержит лист работ, источники и контроль, итог подтверждённой стоимости, примечания, фильтры и закреплённые столбцы. Название включает имя PDF и дату.
- Названия новых объектов в кабинете автоматически получают свободный суффикс при совпадении.

## Эксплуатация

API использует ORM-таблицу `registry.document_jobs` в PostgreSQL. Перед первым запуском владелец схемы выполняет `POSTGRES_OWNER_URL=... python -m backend.documents.install`. Доступ runtime ограничен новой таблицей; прав создавать схемы ему не требуется.

Обработчик запускается отдельно: `python -m backend.documents.worker`, с тем же окружением и каталогом данных. Нужны Poppler, Tesseract rus+eng, Pillow и NumPy. Для небольшого сервера: один последовательный процесс, MemoryMax=384M, CPUQuota=50%, OMP_THREAD_LIMIT=1 и OPENBLAS_NUM_THREADS=1. Dockerfile.documents включает эти библиотеки без голосовой модели. Результат сохраняется после каждой страницы и фрагмента, задания после сбоя возобновляются. Бюджет ограничивает реальные вызовы модели, включая проверки и повторное дробление; продолжение запрашивается отдельно.

## Границы точности

Процент ошибок ≤1% не подтверждён испытаниями. Реальный пример `466_23_1_ОВ_Отопление_и_вентиляция_Изм_1_1.pdf` содержит 83 страницы; проверенные страницы не имеют текстового слоя. На страницах характеристик и ведомостей OCR искажает марки и может терять десятичные запятые. Поэтому неизвестные значения остаются неизвестными, расценки не придумываются, а табличные количества требуют проверки.

Геометрия маршрутов по чертежам не измеряется: длины и площади берутся из явных данных документа. Полный автоматический расчёт любого чертежа без проверки мастером пока не является поддерживаемым режимом. Запись в Битрикс24 выполняется после проверки всех строк и расценок, проверки пустого XLSX по публичной ссылке и явного нажатия «Создать таблицу и объект». Заполненный или изменившийся файл не перезаписывается. После записи проверяется содержимое, создаётся объект со сметой и подключением к Диску. При потере ответа повторная проверка распознаёт уже записанный файл и не создаёт вторую копию объекта.

Основания обработки таблиц и фрагментов: [Tesseract: качество и сегментация](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html), [Pillow: Image](https://pillow.readthedocs.io/en/stable/reference/Image.html).

## Загрузка, отмена и выдача

Файлы сначала выбираются локально. Поле «Что найти?» необязательно; без запроса собираются все монтажные работы. Можно добавить несколько PDF и отправить их одной кнопкой. Для передачи резервируется приватный ID, поэтому отмена удаляет и незавершённую загрузку. Удаление задания убирает его файлы и данные; выполняющиеся OCR-процессы и запросы ИИ прекращаются при обнаружении удаления. Созданные ранее объект и файл Битрикс24 при удалении исходного PDF сохраняются, что указано в подтверждении.

На одной странице под файлами находятся найденные строки, проверка, выгрузки и подключение к Битрикс24. Форму новой выборки можно свернуть. По кнопке «PDF с выделением» скачивается весь исходный документ с полупрозрачными жёлтыми полосами по использованным источникам. Текстовый слой привязывается через координаты Poppler, сканы — через сохранённые координаты OCR. Разметка обозначает источник выборки, а не согласование оплаты.

Рабочие листы Битрикс24 группируются по разделам, сохраняют расценки, плановые объёмы, закреплённые колонки и расчёты по датам. Примечания и страницы источников вынесены в отдельный лист и комментарии к работам. Сохранённый вебхук выбирается из профиля; его секрет не включается в ответы PDF API.
