# PDF-проекты: план и первый рабочий этап

Ветка: `codex/pdf-project-analysis`. Основная ветка `main` содержит объединённую проверенную версию приложения на PostgreSQL. Новые PDF-функции пока не развёрнуты на рабочем сервере.

## Что показал пример

`466_23_1_ОВ_Отопление_и_вентиляция_Изм_1_1.pdf`: 83 страницы, около 10 МБ. На проверенных страницах 1–4 и 82–83 текстовый слой отсутствует. Страница 3 — скан таблицы характеристик вентиляционных установок: марки систем, количества, производительность, мощность и примечания. Нельзя принимать мощность или расход воздуха за объём работ. Нельзя отбрасывать таблицу только потому, что она является картинкой.

Выход ориентирован на `Зп аэродром.xlsx`: категория, наименование работы, единица, объём, расценка, стоимость и примечания. Добавлены страница источника и вопрос для проверки. Высота, стеснённые условия и демонтаж идут в примечания; стоимость и коэффициенты без согласования не назначаются.

## Уже реализовано в ветке

- Отдельная вкладка PDF в общем стиле приложения, загрузка до 50 МБ, очередь и фактические статусы обработки.
- Приватные задания в ORM-таблице registry.document_jobs: пользователи видят только свои документы. Файлы сохраняются по случайному ID вне публичной папки.
- Извлечение текстового слоя pypdf; OCR сканов через Poppler и Tesseract rus+eng. Чертежи не удаляются, а помечаются как схемы/чертежи для дальнейшей проверки.
- Отдельный последовательный обработчик, таймауты OCR, сохранение результата каждой страницы, восстановление заданий после истечения 20-минутной аренды.
- Разбор выбранных страниц через существующее подключение ИИ. За один запрос выбирается до 12 страниц; промпт каждой страницы ограничен 18 000 символами, повторно разобранные страницы пропускаются.
- Для предложений нужна дословная цитата из страницы. Число без подтверждения в цитате заменяется на неопределённый объём с вопросом, а не на ноль. Все предложения остаются черновиками.
- Категории, просмотр цитат и вопросов, Excel-черновик с примечаниями и пустыми расценками. Сметы, отчёты и файлы Битрикс24 автоматически не изменяются.

## Локальная проверка

1. Установить зависимости приложения, включая pypdf. Запустить API и frontend как обычно.
2. Открыть вкладку PDF и добавить файл. В разработке ORM-таблица заданий создаётся в реестре SQLite для тестов; рабочий режим — PostgreSQL.
3. Запустить `python -m backend.documents.worker` с тем же APP_STORAGE, DATABASE_URL_FILE и каталогом data. Для сканов нужны `pdftoppm` и `tesseract` с языками rus+eng. Без OCR задание явно перейдёт в «Нужен OCR», а не выдаст выдуманный результат.
4. После OCR выбрать страницы спецификации/описания и отправить на разбор ИИ; ключ задаётся через существующие настройки приложения. Работник очереди должен иметь тот же доступ к защищённым настройкам.

Для PostgreSQL перед первым запуском владелец схемы выполняет `POSTGRES_OWNER_URL=... python -m backend.documents.install`. Роль приложения получает доступ только к новой таблице; ей не нужны права создавать схемы.

Dockerfile.documents готовит изолированный OCR-обработчик без библиотек распознавания голоса. Запускать по одному процессу с ограничением 384 МБ, одним CPU и общим защищённым хранилищем файлов. На сервере приложения с 1 ГБ памяти тяжёлый OCR не следует включать без проверки нагрузки; предпочтителен отдельный обработчик на втором сервере.

## Следующие этапы и критерии готовности

1. Проверить OCR на страницах 3, спецификациях и реальных чертежах примера. Сохранять координаты таблиц и слов, измерять точность единиц и количеств. Числа из OCR пока считаются требующими проверки.
2. Добавить визуальный анализ схем: маршруты, размеры и высотные отметки; явно разделять известный размер и предположение. Обычная текстовая модель не должна измерять изображения.
3. Собрать единый перечень с устранением дублей между характеристиками, спецификацией и планом. Сохранять все источники, исходные обозначения и историю правок. Не складывать похожие строки автоматически.
4. Добавить редактирование и подтверждение предложений мастером, сопоставление с расценками, коэффициенты особых условий отдельными полями.
5. По подтверждённому перечню запросить публичную ссылку на пустой файл Битрикс24, проверить права и создать отдельные листы по категориям через существующий механизм нормализации. Исходные листы сохранять.
6. Ввести бюджет токенов на задание, отмену/удаление файлов, приоритеты, дедупликацию страниц и метрики ресурсов. Проверить 1000 страниц на ограниченном обработчике до допуска в production.

Проверки первого этапа: разграничение доступа, очередь и восстановление, отсутствие ложного успеха без OCR, проверка цитаты/объёма ИИ и структура Excel. Полноценное чтение геометрии чертежей и запись результата в Битрикс24 ещё не реализованы.
