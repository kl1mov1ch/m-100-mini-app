# Техническое задание «Журнал работ» М100

Редакция от 12 ноября 2026 года. Этот документ задаёт требования к следующим изменениям. Явное уточнение заказчика обновляет соответствующий пункт ТЗ.

## 1. Приложение и доступ

- Основной режим — Telegram Mini App для телефона. Для разработки и проверки доступен обычный браузерный режим на ПК. Технологии проекта — Python/FastAPI, React/TypeScript и Ant Design.
- Администратор управляет доступом по Telegram ID и видит отчёты, историю и показатели по всем объектам. Исправление смет и отчётов относится к работе мастера.
- Мастер видит свои объекты и может создавать новые. Каждый объект ведёт свой справочник, отчёты и подключение к файлу Битрикс24.
- Переключение «Администратор / Мастер» на проде доступно одному настроенному Telegram ID. В режиме мастера действуют обычные ограничения владельца объекта. Все права проверяет сервер.

## 2. Импорт и рабочий лист

- Мастер загружает XLSX или CSV либо подключает книгу с Битрикс24.Диска. Публичная ссылка используется для чтения. Запись требует доступа на изменение файла через вебхук.
- Приложение читает все позиции. Оно находит наименование, единицу, план, расценку и даты по структуре книги. Код определяет однозначные поля, ИИ помогает при сомнении.
- После подтверждения формируется отдельный лист «Журнал работ» по образцу «Незавиисмости 24.xlsx». Исходные листы сохраняются в книге. Загруженный файл можно скачать с рабочим листом. Для связанной книги последующие отчёты пишутся в рабочий лист Битрикс24.
- Рабочий лист содержит название, единицу, план, расценку, стоимость по смете, факт, остаток и дневные объёмы. Новая дата добавляется отдельной колонкой справа. Внизу по каждому дню видны число выполненных позиций, число работников, общая сумма и доля на человека в BYN.
- Подтверждённые данные остаются доступны после перезапуска. Повторная запись того же дня заменяет объёмы этого дня и пересчитывает итоги.

## 3. Замечания и быстрые исправления

- На рабочем экране одно короткое уведомление. Повторяющиеся ошибки дневного объёма группируются по листу, столбцу и дате. Карточка показывает диапазон и число проблемных ячеек.
- Для целого дневного столбца доступны действия «Восстановить по отчёту», «Заполнить нулями» и «Убрать колонку». После выбора мастер один раз подтверждает запись. Нули заменяют пустые и нечисловые ячейки, действительные объёмы сохраняются. Удаление исключает дату и её объёмы из расчёта, сохраняя соседние даты и адреса их ячеек.
- При восстановлении приложение берёт значения за ту же дату из подтверждённого отчёта или ранее прочитанной версии. ИИ может подсказать подходящий вариант или единицу измерения. Фактический объём и расценка берутся из проверяемого источника. Когда данных недостаточно, мастер видит короткую подсказку и выбирает ноль, удаление или ручной ввод.
- Для единичной ошибки можно исправить ячейку вручную. Ясный ввод вроде «12 м» преобразуется в число при совпадении с единицей сметы.
- Перед записью сервер сверяет данные, формулы и оформление. Служебное пересохранение Excel не мешает записи. При ручной правке открывается актуальная проверка с коротким описанием изменения. После записи сервер перечитывает изменённые ячейки.
- Изменение заливки показывается отдельно. Мастер может нажать «Оставить», чтобы принять оформление. Принятая отметка сохраняется при следующих записях журнала.

## 4. Расхождения приложения и Битрикс24

- Приложение проверяет связанную таблицу при открытии объекта и по кнопке обновления. Для расхождений объёмов, плана или расценок мастер видит краткую сводку и два действия.
- «Заменить в приложении» принимает проверенные значения из Битрикс24. Пустой дневной объём означает ноль. Приложение сохраняет историю замены.
- «Заменить в таблице» записывает подтверждённые значения приложения в рабочий лист. Перед обеими операциями видно, где изменятся данные. При изменении файла или отчёта после проверки нужна свежая сводка.
- Структурные изменения сметы, требующие сопоставления работ, открываются в компактной проверке. Обычная новая запись мастера проходит подтверждение и синхронизацию по стандартному сценарию.

## 5. Отчёт мастера

- В разделе «Отчёт» есть отдельные кнопки «Текст» и «Голос». Текст можно вставить прямо на экран. Голосовая панель возвращает распознанный текст, результаты подбора появляются в самом отчёте.
- Сначала используется поиск по смете объекта. ИИ уточняет неоднозначные позиции и число работников, если оно названо. Мастер видит варианты, редактирует объёмы и подтверждает итог.
- Календарь поддерживает свайп по месяцам, кнопки навигации и отметки дней с работами. Открытие календаря не вызывает клавиатуру. Даты и время интерфейса — по Минску.
- Суммы рассчитывает код. До отправки мастер видит изменения объёма, число работников, итог дня и долю. История фильтруется по доступным объектам и датам. Excel скачивается файлом на устройство.
- Интерфейс рассчитан на телефон. Основные действия видны сразу, предупреждения короткие, поля и кнопки помещаются на узком экране.

## 6. Приёмка изменений

| Сценарий | Ожидаемый результат |
| --- | --- |
| В столбце P 70 текстовых ячеек под датой | Одно замечание с листом, диапазоном и датой. Каждое из трёх действий применяется к столбцу после одного подтверждения. |
| Удалён объём в связанном листе | Отображается краткая сводка. Замена в приложении принимает ноль. Замена в таблице возвращает подтверждённый объём. |
| Книга изменилась во время проверки | Устаревшая операция отклоняется, мастер получает предложение перечитать данные. |
| Загружен образец с 70 работами и семью датами | Рабочий лист содержит все 70 работ, семь дат и дневные итоги. Значения и формулы исходного листа сохранены. |
| Повторно исправлен отчёт за день | Меняются объём, сумма и доля нужной даты. Соседние даты сохранены. |
| Мастер ввёл текст или голос на телефоне | Варианты видны на экране отчёта. Календарь помещается в окне. Чужой объект недоступен. |

Перед выкладкой проверяются сборка, серверные тесты и затронутые сценарии. После выкладки проверяется работа новой версии. Реальная запись в рабочую книгу требует выбора действия мастером либо прямого поручения заказчика.

## 7. Дальнейшие задачи

Миграция рабочей базы на PostgreSQL и анализ больших PDF ведутся отдельно. Для каждого этапа до разработки фиксируются сценарий, условия переноса данных и критерии приёмки.
