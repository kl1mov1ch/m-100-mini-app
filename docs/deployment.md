# Развёртывание из GitHub

Один Linux-сервер с Docker Engine и Compose v2. Приложение состоит из FastAPI с собранным React, Nginx и отдельного запуска Certbot. Веб-приложение и API используют один HTTPS-домен. Для локального распознавания small требуется запас памяти; начальная конфигурация — 2 CPU и 4 ГБ RAM. Модель скачивается при первом распознавании.

## Перед запуском

Нужны IP сервера, SSH-доступ, свободные порты 80/443, домен с A-записью на сервер и email для сертификата. AAAA-запись должна указывать на этот же сервер либо отсутствовать. Если на сервере уже работает Nginx, конфигурацию нужно встроить в него: второй процесс не займёт те же порты.

```bash
git clone https://github.com/kl1mov1ch/m-100-mini-app.git
cd m-100-mini-app
cp deploy/.env.production.example deploy/.env.production
mkdir -p deploy/secrets
chmod 700 deploy/secrets
umask 077
read -rsp 'Telegram token: ' bot_token
printf '%s' "$bot_token" > deploy/secrets/telegram_bot_token
unset bot_token
```

В `deploy/.env.production` укажите числовой `TELEGRAM_ADMIN_IDS` и точный `APP_ALLOWED_ORIGINS=https://ваш-домен`. Токен хранится в Docker secret, не в Compose. Все эти файлы исключены из Git. Ключ DeepSeek можно подключить через настройки приложения после входа администратора. Настройки Битрикс задаются отдельно у каждого объекта.

## Первый HTTPS-запуск

```bash
bash deploy/enable_https.sh app.example.com admin@example.com
docker compose ps
curl --fail https://app.example.com/healthz
docker compose exec -T app python scripts/configure_telegram.py --url https://app.example.com
```

До получения сертификата HTTP-конфигурация возвращает 503 для приложения и обслуживает только проверку домена. После выпуска сертификата запускается приложение, проверяется конфигурация Nginx и включается HTTPS с перенаправлением HTTP.

Кнопка меню бота создаётся через официальный Bot API. В BotFather дополнительно настройте Main Mini App: `/mybots` → бот → Bot Settings → Configure Mini App, URL — тот же HTTPS-адрес. Это включает кнопку запуска в профиле и ссылку `https://t.me/имя_бота?startapp`. Само приложение не требует обработчика сообщений или polling бота.

Вход вне Telegram на production закрыт. initData проверяется по подписи бота и времени. Выданный доступ проверяется на каждом запросе. Сервер не создаёт демонстрационные объекты и не принимает локальный профиль администратора. Перед production-запуском автоматическая проверка отклоняет пустой токен, ID администратора или HTTPS-origin.

## Обновление и сертификаты

```bash
bash deploy/update.sh
bash deploy/renew_https.sh
```

Запускайте обновление сертификата ежедневно через cron/systemd с абсолютным путём к `renew_https.sh`. После `certbot renew` Nginx перечитывает сертификат. GitHub Actions проверяет Python, React и сборку Docker при каждом push. Он не получает SSH-ключи и не выкатывает изменения на неизвестные серверы. Сценарий обновления получает `main` через `git pull --ff-only`, пересобирает приложение и ждёт исправного состояния.

## Постоянные данные

Все базы, ключи провайдеров, загруженные таблицы и модель речи находятся в Docker volume `app_data`, подключённом к `/app/data`. Обновление кода этот том не удаляет. Не выполняйте `docker compose down -v`: это удаляет рабочие данные. Используется один процесс приложения; несколько экземпляров с независимыми SQLite-базами не поддерживаются.

Для переноса существующих локальных данных используйте `scripts/data_archive.py`: `backup путь.zip` создаёт отдельную копию SQLite и незавершённых импортов, `restore путь.zip` восстанавливает в пустую папку данных и исправляет пути объектов для нового сервера. Архив содержит секреты и рабочие сведения, храните и передавайте его приватно; в Git он не отправляется. На время окончательного переноса остановите запись в локальное приложение. Перед обновлениями делайте резервную копию.

## Проверка в Telegram

Откройте кнопку меню бота на Android, iOS и Desktop. Проверьте вход администратора, выдачу доступа мастеру, изоляцию объектов, загрузку таблицы, ввод с клавиатуры и запись/загрузку аудио. Кнопка Telegram «Назад» закрывает текущую панель или возвращает к объектам. При несохранённых изменениях включается подтверждение закрытия. Учитываются safe area Telegram и изменения высоты окна. Используется светлый интерфейс приложения с согласованным цветом шапки Telegram. Полный экран не запрашивается принудительно.

SDK подключён по [документации Telegram Mini Apps](https://core.telegram.org/bots/webapps), HTTPS и проксирование — по [документации Nginx](https://nginx.org/en/docs/http/ngx_http_proxy_module.html). Реальную запись в Битрикс проверяйте после предоставления вебхука с правом «Диск»: публичная ссылка даёт чтение, но не серверную запись.
